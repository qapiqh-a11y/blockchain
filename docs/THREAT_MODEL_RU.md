# Модель угроз — вариант 13 «Транспорт / электронный билет»

| № | Угроза | Возможный сценарий | Последствие | Мера защиты |
|---|---|---|---|---|
| 1 | Несанкционированное изменение статуса | Посторонний адрес пытается вызвать validate/revoke | Поддельная валидация или отзыв билета | OpenZeppelin AccessControl, OPERATOR_ROLE, тесты отрицательных сценариев |
| 2 | Компрометация административного ключа | Злоумышленник получает DEFAULT_ADMIN_ROLE | Назначение собственных операторов/аудиторов | Разделение ролей; в production — multisig, timelock/AccessControlDefaultAdminRules, мониторинг RoleGranted/RoleRevoked |
| 3 | Подмена/утечка конфиденциальных данных | Персональные данные билета записываются публично on-chain | Нарушение конфиденциальности | Хранить документы off-chain; on-chain — только ticketId, routeCode/status и dataHash |
| 4 | Повторная регистрация / replay бизнес-операции | Один ticketId регистрируется повторно | Дублирование объекта и неоднозначность состояния | exists + TicketAlreadyExists; уникальность ticketId; nonce Ethereum защищает повтор той же tx |
| 5 | Ошибка авторизации через tx.origin | Администратор вызывает вредоносный промежуточный контракт | Контракт-посредник выполняет привилегированную операцию | Никогда не использовать tx.origin для auth; msg.sender + AccessControl |
| 6 | Front-running / опережение транзакции | Наблюдатель пытается первым отправить операцию с известным ticketId | Захват идентификатора/нарушение бизнес-процесса | Только OPERATOR_ROLE может писать; при необходимости commit-reveal/off-chain authorization |
| 7 | DoS / злоупотребление входными данными | Невалидные или огромные структуры делают функцию дорогой | Рост gas / отказ обработки | Фиксированный минимальный набор данных, bytes32 вместо больших строк, input validation, отсутствие неограниченных циклов |

## Границы доверия

- Пользовательскому frontend/dApp нельзя доверять как источнику истины: контракт повторно проверяет права и входы.
- RPC/provider и block explorer рассматриваются как внешние сервисы; критические результаты можно сверять вторым RPC/узлом.
- Административный ключ — критический актив; в учебной версии это EOA, в production — multisig/timelock.
- Off-chain storage должен обеспечивать собственную аутентификацию, контроль доступа и резервирование.
